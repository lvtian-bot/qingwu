# 会话与项目

## 职责

- dsh 保存会话、项目注册表、运行状态与对话事件；界面只维护当前会话的展示投影、临时输入草稿和侧栏交互状态。
- 侧栏分区分组交互：支持对「置顶」「项目」「会话」三大分区进行整体折叠与展开。折叠状态持久化于本地存储并在重启后保持；搜索过滤态下所有分区与项目临时展开，标题折叠切换禁用，不改写保存偏好，退出搜索后恢复。
- 项目分组只记录「已折叠」的项目，未登记的项目默认展开；当前会话所在项目强制展开并禁用标题折叠切换，离开后恢复保存偏好。所有新建入口（项目行、顶部新建、首次发送/命令、项目切换）在成功创建或复用空白会话后统一展开目标项目；打开已有会话不改写偏好。删除成功后统一清理折叠记录，流中实际移除项目也会清理。
- 每个项目默认露出 5 条会话，每点一次「展开显示」多一批，点「收起」或折叠项目后复位回默认条数；这一展开水位只在本次运行内有效，不持久化。运行中、等待用户回应、后台完成未读以及当前会话的条目会无视默认条数自动露出（最多 50 条）。
- `useEngineStreams` 订阅全局 `$events`、`workspace/follow` 和选中会话的 `session/follow`，将快照与增量折成对话、队列、运行状态和待处理项；`NativeApp` 组合输入、会话操作、滚动和决策回执。
- 新会话落到当前或最近活跃项目（或无工作区模式）。项目选择 chip 提供「无工作区」与已有项目选项，切换 chip 时建或复用目标工作区（或独立会话）的空白会话，各项目未发送草稿独立保留在原项目，不跨项目迁移；已有会话的项目归属不能靠 `workspace/insertSessionBefore` 跨项目改写。
- 定时任务：侧栏「新会话」下方入口打开独立管理页，消费引擎 `schedule/catalog|update|delete|history` 维护任务列表（标题、频率、下次运行、所属会话）、编辑（compare-and-set）、删除与运行历史；dsh 无界面创建端点，创建引导为「新开会话并预填示例指令」，由 AI 经 `schedule_create` 工具建任务。

## 主要代码入口

- 会话与项目：`src/renderer/src/native/useEngineStreams.ts`、`useSessionActions.ts`、`SessionSidebar.tsx`、`SidebarRows.tsx`、`sidebar-data.ts`。
- 定时任务：`ScheduleTasksPage.tsx`、`useScheduleTasks.ts`；端点与 wire 类型在 `protocol.ts`。
- 对话与输入：`NativeApp.tsx`、`events.ts`、`TurnItems.tsx`、`Composer.tsx`、`ChatComposer.tsx`、`useComposerDrafts.ts`、`useChatScroll.ts`。
- 审批、问答与队列：`PendingInteraction.tsx`、`QueueStrip.tsx`、`RunningStrip.tsx`；协议入口在 `protocol.ts`，实际请求经 `rpc.ts` 与主进程桥转发。

## 易复发的技术约束

- **侧栏展开与持久化**：临时展开只影响显示，标题图标、子列表和可切换状态必须使用一致规则；创建、删除失败不得改变保存偏好，成功后收尾由 `useSessionActions` 的统一回调执行，不散落到按钮中。列表变化只清理本次运行已经出现后又移除的 ID（含最后一个项目），不能用初始空列表或首次非空列表推测删除或基线就绪。项目名省略仅作用于文字子元素，收起箭头独立占位。回归验证见 `tests/sidebar-state.test.cjs`；历史问题见 [侧栏展开状态问题记录](侧栏展开状态问题记录.md)。
- **侧栏切换引起过黑屏**：`NativeApp` 曾因 React Hook 条件调用破坏渲染顺序。组件每次渲染时必须以相同顺序调用 Hook，不能将它放进条件分支或早返回之后；错误边界和诊断日志只帮助发现问题，不替代修正 Hook 结构。
- **会话分叉**：`session/fork` 的 `atSeq` 是包含切点的日志事件 seq，界面从正式答复条目的 `seq`（与条目 key 同源）取值，分叉即复制截至该轮答复的完整前缀并收束开放轮次。引擎不复制标题、模型回到默认选择：界面分叉后须补「源标题 · 分支」改名并延续源会话 `modelSelection.next`；子会话由引擎自动挂到源工作区。分叉按钮只挂已收束轮次的正式答复上，会话运行中不提供（规避 `session/agent-busy`）。
- **会话实时输出**：当前 `session/follow` 订阅需声明 `assistantStream: true`，文本和思考增量由 `assistant-stream` 帧提供。开场快照可包含在飞内容的压实基线；检测到 revision 跳号时应重开订阅并用新快照重建，不能继续拼接旧增量，否则会漏字或重复。
- **历史翻页**：切换会话、重开订阅或收到新快照，都会使旧翻页请求失效；仅在有效响应即将前插时记录滚动锚点。会话流打开失败或异常结束要解除加载态并报错，避免界面一直转圈。
- **草稿与发送**：提交前记录草稿版本和所属会话；发送失败只恢复仍未被再次编辑的原会话草稿，切到其他会话后不能覆盖当前输入。首次发送创建会话后，空白页草稿须清理并在失败时恢复到新会话。
- **附件选择与文件提及**：输入框左下角附件按钮与拖拽/粘贴支持全格式文件接入。图片自动进入多模态草稿附件，非图片文件与目录根据会话工作区（cwd）转换为标准 `@相对路径`（含空格自动加引号）插入输入框，对齐 DSH 桌面端 Agent 文件工具使用规范。
- **发送回显与排队分流**：空闲状态（!running）发送直接将乐观回显置入主对话流末尾，避免在输入框上方的排队栏（QueueDock）闪现导致界面高度抖动；运行中的忙碌状态发送才归入输入框上方的排队栏，供用户编辑、撤回或插话。
- **运行状态**：`api-session/status` 只在状态变化时推送，切换会话和断线重连不能依赖它重播；进入会话时从会话列表快照播种状态，后续再由事件更新。
- **指令执行的可见性**：宿主斜杠指令由引擎写 `command/run`、`command/done` 日志事件，界面把它们折成对话流里的指令卡（执行中 → 结果/失败原因就地显示），不能只靠顶部错误提示条——成功时静默会让用户以为指令没执行。指令与压缩条目是用户主动发起的独立动作，不能被轮次过程折叠收起，只在折叠行上记数量。
- **压缩的呈现**：手动 `/compact` 走 `compaction/start` → `compaction/summary` → `compaction/end`；完成统计取 `shadowedSeqs.length` 与 `shadowedTokenCount`，摘要取 `summary` 的文本块。压缩完成会在日志里补一条 `user/message`（`source.kind === "compact-checkpoint"`，replace 表面），它是标记而非用户输入，绝不能渲染成用户消息气泡。
- **`/export` 归客户端执行**：官方 `/export` 由 web-app 层注册（`session-log-download`），青梧 profile 只加载 dsh-base 与自身补丁层，引擎里没有这条指令。界面按客户端命令处理，经主进程读 `~/.dsh/sessions` 下的会话（含子会话）日志打包 ZIP 落到系统下载目录，日志为 `.jsonl.zstd` 时先解压再打包。
- **`/feedback` 不提供**：青梧不采集会话反馈（遥测链已裁剪、无反馈面板），引擎里该指令即使执行成功也无人消费，因此不进入指令菜单。
- **待处理项归属**：`$events` 是全局流，审批和问答帧的 `agentId` 是所属会话 ID。待处理项必须带会话归属，不能做成所有会话共用的扁平界面列表；决策回执的信封约束见 [dsh 运行与连接](../dsh运行与连接/dsh运行与连接.md)。归位上溯（待处理项沿 `parentSessionId` 归到根会话）只对 `origin === "subagent"` 的子代理会话发生——分叉会话的摘要同样带 `parentSessionId`（引擎 fork 写入用于溯源），但它自己可见，待处理项必须归到自己，否则审批卡片会串到源会话。
- **定时任务契约**：引擎只有 catalog/update/delete/history 四个界面端点，创建由 AI 的 `schedule_create` 工具完成，界面不得自建客户端定时投递。`schedule/update` 是 compare-and-set：必须回传编辑前完整记录（目录项须剔除 `sessionId`/`status`/`lastDelivery` 扩展字段），冲突时重读目录再编辑。`schedule/changed` 事件不经当前桥接层转发，列表以「打开页面拉取 + 操作成功后重拉」保持新鲜，不要假设有实时推送。周期任务的 `scheduledAt` 即下次计划时间（投递后由引擎推进），展示无需客户端推算。任务只在青梧运行期间触发，页面须保留该说明。
