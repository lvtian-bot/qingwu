# 青梧技术总览

本文记录整体架构、跨模块流程和模块入口。模块内部实现及容易再次踩到的技术约束由对应模块说明展开；dsh 版本以 `package.json` 与锁文件为准。

## 技术边界

青梧是 Electron 桌面客户端。自有代码使用 TypeScript、React；Windows 安装包由 electron-builder / NSIS 构建。`@deepseek-ai/dsh` 作为随包 npm 依赖运行在独立 Node 子进程中，负责 Agent、会话、工具、模型、沙箱与 Skill。青梧不 fork 引擎、不另实现 Agent Loop，也不另存一份引擎业务数据。

```text
界面（React） → preload / IPC → 主进程 DshBridge ─→ dsh 服务（独立 Node 子进程）
```

主进程管理应用启停、窗口、托盘、更新及 dsh 子进程；preload 只暴露受限 IPC。界面消费主进程转发的 RPC 与事件流。`src/shared/types.ts` 定义 IPC 类型，`src/shared/dsh-wire.ts` 解析桥接信封；界面消费的引擎协议集中在 `src/renderer/src/native/protocol.ts`。

## 关键跨模块流程

### 启动与建立连接

1. 主进程先设置应用数据路径、取得单实例锁和隐藏控制台，创建窗口、引擎及通信桥管理器；应用就绪后准备托盘并等待 `HarnessManager.start()` 完成引擎启动与就绪探测。
2. 引擎就绪后创建主窗口并启动通信桥。`DshBridge` 获取鉴权信息、建立多路复用连接；preload 向界面提供受限的请求、订阅和连接状态接口。
3. 界面挂载后订阅全局事件、工作区与当前会话流，建立会话列表和对话的展示投影。引擎业务数据由 dsh 保存，主进程负责进程及连接生命周期，界面不另建一套业务存储。

启动顺序由 `src/main/index.ts` 组织；引擎就绪前的失败会进入启动错误处理，不把窗口创建当成引擎已经可用。启动与连接细节见 [桌面应用](桌面应用/桌面应用.md)和 [dsh 运行与连接](dsh运行与连接/dsh运行与连接.md)。

### 消息发送与响应展示

1. `NativeApp` 接收输入，先区分宿主或客户端指令与普通消息。普通消息在连接可用时提交；没有当前会话则先创建会话，再应用空白页选定的模型。
2. 界面记录草稿版本，并按当前是否正在运行，将临时回显放入对话流或排队栏。请求经 `rpc.ts`、preload 和主进程通信桥传入 dsh；发送失败时移除临时回显，并按草稿版本和会话归属恢复输入。
3. dsh 执行任务并通过订阅流提供会话记录、输出增量和运行状态。`useEngineStreams` 消费快照与增量，`events.ts` 形成展示条目，`TurnItems` 等组件渲染消息、工具和指令结果。审批与问答来自全局事件流，须保留会话归属，决定回执仍经同一通信桥提交。

请求返回与流式输出分别承担提交结果和持续展示，界面不能仅因本地回显成功就认定消息已持久化。草稿、排队和审批细节见 [会话与项目](会话与项目/会话与项目.md)。

### 断线与状态恢复

1. 通信桥在连接关闭时通知界面，并安排重连；连接恢复后重开仍登记的逻辑流。界面的手动重连入口同样调用通信桥，不直接启动引擎进程。
2. 当前会话收到新快照后，用快照替换日志基线、恢复在飞输出，并使旧历史翻页请求失效；输出增量的 revision 不连续时，取消旧订阅并重新获取快照，避免在不完整基线上继续拼接。
3. 连接恢复不等于引擎已经重启。引擎意外退出由主进程显示错误；通信桥的自动重连只恢复通信，不负责重启引擎。设置页在断开转为连接时刷新联网搜索配置、修订号和凭据状态，并保留未保存的草稿。

这些边界使主进程管理连接、各消费模块管理自己的状态恢复，避免连接层推测业务状态。订阅和快照约束见 [dsh 运行与连接](dsh运行与连接/dsh运行与连接.md)、[会话与项目](会话与项目/会话与项目.md)及 [设置与模型](设置与模型/设置与模型.md)。

## 跨模块约定

- **引擎数据归属**：项目、会话、模型供应商和权限以 dsh 为准，经其 API 操作；应用设置同存于 `~/.dsh` 的青梧 profile 目录，由主进程直写而不经引擎 API。界面里的草稿、折叠与宽度等展示状态不能当成引擎持久化数据。
- **应用默认配置**：通过随包的原生 dsh 配置 bundle 提供，位于基础 bundle 之后、用户配置之前；主进程仅初始化 profile 清单，不解析或重写用户引擎补丁。搜索配置与凭据仍由 dsh 设置及凭据接口持久化，详见 [设置与模型](设置与模型/设置与模型.md)。
- **界面语言**：语言偏好存于应用设置 `uiLanguage`（auto 跟随系统），渲染层与主进程共用 `src/shared/i18n-core.ts` 的解析与插值规则；渲染层词条按域拆分（`src/renderer/src/i18n/`），主进程可见文案独立小词典（`src/main/i18n.ts`）。机制与约束见 [界面与视觉设计](界面与视觉设计/界面与视觉设计.md)。
- **通信路径**：界面不直连 dsh 的 `/api`，由主进程桥代理；一元请求使用 `POST /api/<endpoint>` 的 `client-request` 信封和 `{ args: ... }` 载荷；逻辑流共用 `/api/remote.mux`。鉴权信息只留在主进程，日志和错误不得泄露 token、cookie 或密钥。具体回执和重连约束见 [dsh 运行与连接](dsh运行与连接/dsh运行与连接.md)。
- **实时状态**：`$events` 承载全局通知及审批/问答，`workspace/follow` 承载项目状态，`session/follow` 承载选中会话快照与增量。WebSocket 重连会重开已注册逻辑流，但不会自动重启 dsh 进程；会话投影仍须用新快照重建，不能只拼接旧增量。
- **引擎版本**：dsh API 有兼容性破坏风险。升级依赖时核对已安装版本的 controller 约定和契约测试，再验证会话、审批、流式输出与命令执行；客户端界面不等于可以直接替换引擎地址。
- **随包运行时**：Windows 安装版使用随包的控制台子系统 `node.exe` 启动 dsh；版本应与 Electron 内置 Node 对齐。引擎和插件需真实 `node_modules` 路径，故打包保留 `asarUnpack: ["node_modules/**"]`。原因与降级边界见 [dsh 运行与连接](dsh运行与连接/dsh运行与连接.md)。
