# 设置与模型

## 职责与数据归属

- 青梧应用设置由主进程 `SettingsManager` 管理，写入 dsh profile 目录 `~/.dsh/profiles/qingwu/app-settings.json`（设置 `DSH_HOME` 时跟随数据根），与引擎配置同住 `.dsh`；旧版 `userData/settings.json` 在启动加载时一次性搬移并留档。设置包含关闭到托盘、界面模式、过程折叠和聊天宽度；窗口位置尺寸另由 `WindowStateManager` 保存在应用 `userData/window-state.json`。侧栏和右面板宽度等界面偏好使用 renderer `localStorage`。
- 模型供应商、凭据状态、默认模型和默认权限属于 dsh 配置，青梧通过引擎设置与会话 API 读写，不在应用设置里维护第二份。设置页展示通用设置、模型、联网搜索、权限与归档会话；会话输入区提供当次模型和权限选择。
- 联网搜索提供 dsh 的 DeepSeek 新版 API 与 Exa 两种服务，连接地址与插件参数均不向用户暴露（DeepSeek 地址由引擎默认固定，Exa 全部使用插件默认值）。DeepSeek 新版为默认并支持沿用模型密钥；Exa 需用户单独配置 Exa API 密钥，保存后需重启应用生效。旧版 Messages 搜索已下线：存量用户打开设置页时静默迁移到新版，失败则按外部配置展示并允许手动切换。已有未知服务或不同抓取搭配保持原样，只有明确切换服务时才修改选择。约束和核查依据见 [联网搜索问题记录](联网搜索问题记录.md)。
- 会话内模型切换走 `session/selectModel`，空白页选择先暂存在界面并随新会话建立应用；会话内权限切换执行宿主 `/permission` 命令，空白页更改的是新会话默认权限。

## 主要代码入口

- 应用设置：`src/main/settings.ts`、`dsh-paths.ts`、`window-state.ts`、`paths.ts`、`src/shared/types.ts`、`src/renderer/src/native/GeneralTab.tsx`、`usePanelWidth.ts`。
- 引擎设置与供应商：`src/renderer/src/native/SettingsPage.tsx`、`ModelsTab.tsx`、`ProviderDetail.tsx`、`CustomProviderCreate.tsx`、`WebSearchTab.tsx`、`useDshSettings.ts`、`useWebSearchSettings.ts`、`web-search-settings.ts`、`useProviderDirectory.ts`、`settings-domain.ts`。
- 会话选择器：`src/renderer/src/native/useModelSelection.ts`、`ComposerControls.tsx`、`CandidateModelPicker.tsx`；端点和数据类型在 `protocol.ts`。

## 技术约束

- 应用设置与引擎配置统一存于 `.dsh`，路径解析统一走 `dsh-paths.ts`（优先 `DSH_HOME`），不得在 userData 维护第二份应用设置。设置读写不依赖引擎进程，主进程同步完成，托盘关闭行为等启动早期逻辑可用；因此应用设置不经引擎 settings API，也不占用其命名空间。通用设置收拢为单一「青梧配置目录」入口，支持打开专属 profile 目录（`~/.dsh/profiles/qingwu`）及用系统编辑器打开引擎补丁文件（`cordis.patch.yml`），不向用户暴露底层的 userData 系统缓存目录。
- `settings/describe` 提供引擎命名空间当前值、写入能力和 revision。更新默认模型、权限或供应商配置时应携带当前 `expectedRevision`；失败后重新读取，不能只把界面本地状态当作已持久化。
- 新会话默认模型在引擎 `agent-default-model` 命名空间；清空选择通过 `settings/mutate` 移除 `provider`、`model` 字段，回到继承配置，不写空模型。默认权限在 `permission.defaultPreset`，与会话内的权限选择不同。
- 模型目录与设置读取可能失败；选择器可降级，但失败不得伪装成保存成功。API 密钥只经引擎支持的凭据机制操作，不写入青梧设置、文档或日志。
- 供应商卡片的连接参数（`baseURL` 与 `api`）只对用户自声明的路由展示；内置服务商的地址与协议由适配器固定，界面不提供编辑入口。服务商选择列表把内置服务商排在前面，自定义入口排在末尾。

## 联网搜索约束

- 默认层由 `packages/dsh-profile` 声明（含 Exa 搜索插件的启用行，不写任何密钥 config），通过 dsh 原生 bundle 在基础层之后、用户层之前组合；初始化与加载顺序见 [dsh 运行与连接](../dsh运行与连接/dsh运行与连接.md)。不得根据用户补丁是否为空推断是否选择过搜索，也不得重写用户补丁来升级默认值。
- `web` 保存检索与抓取提供方（`searchProvider`/`fetchProvider` 均为引擎声明的运行时可修改字段）；`web-deepseek-api` 管理新版 `count`（1–50、默认 10）。连接地址不属于界面配置。`dsh-tool-web` 的返回上限是另一项工具配置，不将其默认值 8 当作搜索服务硬限制。
- 旧版 `deepseek-official` 搜索已下线：设置页加载检测到该存量选择且配置可写时，静默写入 `web` 切换到新版（unset 恢复默认层值），失败不阻塞加载、下次再试；配置只读时不迁移，按外部配置展示。
- 保存先写目标服务的变更字段，最后写 `web` 的服务选择，均携带 revision。清空数值使用 `unset` 恢复继承值或默认值；未修改字段不写入。每次保存只保存当前选中的服务，切换服务前的未保存草稿保留在当前设置页内。
- DeepSeek 默认凭据引用沿用 `llm-deepseek.apiKeyEnv`；独立搜索使用各自引用，经原生 `credentials/set` 保存，不写模型共用引用；已有独立搜索引用保持不变。预设搜索引用若与模型引用重名，改用不同的搜索引用，并查询实际目标的凭据状态和可写能力。明确切换密钥来源或替换密钥时，若存在优先生效的字面密钥，通过空覆盖停止该字面值，避免新引用被旧密钥遮盖。界面只使用脱敏状态，不回显明文；“已配置”不表示完成联网验证。
- Exa 插件未声明任何运行时可修改字段（volatile 契约），引擎设置接口不暴露其命名空间、也拒绝对其写入；插件也不接入凭据体系（凭据库从不注入环境），只读启动环境的 `EXA_API_KEY`。因此 Exa 接入只做两件事：切换 `web` 的服务选择（正规渠道），以及把密钥写入 dsh 用户环境层 `$DSH_HOME/.env`（主进程 `user-env.ts` 经 IPC 执行，仅维护 `EXA_API_KEY` 一行，权限 0600）；不写任何插件配置，条数等使用插件默认值。用户环境层同时是引擎启动环境与凭据状态查询回退链的组成层，界面"已配置"状态经凭据查询回退自然成立。插件在构造时快照启动环境，密钥更新后需重启应用（引擎随之重启）才生效，保存成功时界面提示重启。
- 初始凭据状态为未知；仅在查询确认可写后允许输入。配置可写与凭据可写分开判定；配置只读时，仅允许轮换已经正确绑定且可写的独立凭据。后到的旧查询回执不能覆盖新状态。
- 翻译更新不重建加载生命周期；普通刷新只更新未编辑字段。部分保存失败后回读快照，保留尚未保存的草稿；已保存的凭据不回滚或要求重复输入。成功回读前不显示保存成功。
- 加载错误和操作错误分别保存；当前配置回读成功后清除旧加载错误，仍保留尚未解决的保存错误。不能用一次成功的读取替代保存成功，也不能因连接恢复后残留加载提示而误报不可用。
- 设置页每次真实断开到连接的转换都重新读取搜索配置、修订号和凭据状态；此前已加载成功不构成跳过刷新的条件。初次挂载由设置 hook 加载，稳定连接及就绪状态变化不重复触发；刷新沿用草稿重基，只更新未编辑字段。
