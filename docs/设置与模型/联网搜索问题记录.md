## 产品目标

- 新安装及未主动选择其他搜索服务的升级用户，默认使用 DeepSeek 新版搜索；修改模型或权限不应阻止搜索默认值升级。
- 搜索服务可独立于聊天模型选择。已有明确搜索选择应被保留。
- DeepSeek 搜索默认使用已配置的 DeepSeek 模型凭据；单独设置搜索密钥时，只影响搜索。
- 服务选择、调用、凭据、配置持久化和重置均沿用 dsh 已有能力；不新增搜索适配器、转发协议或自动回退机制。

### 官方搜索设置页的处理方式

`dsh-client-ui-settings-web-search` 的现成页面只管理 DeepSeek 两种方式，不是通用搜索服务管理页。

- 分别管理 `web` 中的服务选择、`web-search-deepseek` 和 `web-deepseek-api` 中的配置。
- 先保存目标服务的配置，再保存服务选择；前者失败时不启用目标服务。
- 清空字段或恢复默认通过 unset 回到继承值，不等于强制写入官方地址。
- 未修改字段不写入；实际值、继承值和用户覆盖分开处理。
- 凭据引用取自对应设置节的 `apiKeyEnv`，通过凭据服务保存并回读状态。
- 新版接口的搜索结果条数为 1–50、默认 10；`dsh-tool-web` 的结果上限默认值 8 是另一个配置项，不是引擎不可更改的硬限制。

依据：已安装 `dsh-client-ui-settings-web-search/README.zh.md`、`lib/client.js`，以及 `dsh-web-deepseek-api/lib/index.js`、`dsh-tool-web/README.md`。

## 修订前问题与处理结果

| 触发场景 | 可见后果或风险 | 已实施处理 |
| --- | --- | --- |
| 现有搜索服务不是 DeepSeek，保存端点或条数 | 仍修改 DeepSeek 设置，可能提示成功却不影响当前搜索 | 识别新旧 DeepSeek 完整检索与抓取搭配；其他搭配保持原样，未明确切换时禁止写入 DeepSeek 设置 |
| 在搜索页填写新密钥 | 默认仍写模型共用引用，可能影响聊天 | 独立模式写入搜索专用引用；沿用模式只读模型凭据，原有独立引用保持不变 |
| 老用户只改过模型或权限 | 最新提交跳过非空配置，无法获得新的搜索默认值 | 增加原生配置 bundle，在基础层之后组合默认值；用户补丁原样保留，不按文件内容推断升级条件 |
| 保存服务切换时，第二次写入失败 | 服务已切换，端点配置尚未保存，实际请求可能仍发向旧地址 | 采用官方顺序：目标服务配置先落盘，服务选择最后提交 |
| 初次加载凭据状态较慢 | 设置先就绪，凭据仍以乐观初始值显示为可编辑 | 配置和凭据分别维护未就绪、失败和可写状态 |
| 配置包含优先级更高的字面密钥 | 更新凭据引用后可能仍使用旧密钥 | 显式切换来源或替换密钥时清空优先生效的字面值，使用脱敏状态判断；保存凭据后回读确认 |
| 编辑未保存内容后切换界面语言 | 翻译函数变化触发重新加载，可能清除草稿 | 加载生命周期与翻译函数身份解耦；刷新快照和编辑草稿分开处理 |
| 配置初始化写入中断 | 文件可能残缺，后续启动无法恢复 | 复用已依赖的 `dsh-atomic-write`；不再独立维护另一套原子写入实现 |
| 界面显示“有效密钥” | 仅检测到已配置，未实际验证服务可用 | 改为“已配置密钥”，不宣称完成联网验证 |

- 下一步：在现有目录加载函数内增加请求代次或取消保护，确保配置视图与目录结果都仅由最新请求发布，并补充不同阶段的乱序回执测试；不另建后台刷新模块。

### 设置精简与 Exa 接入

2026-10-24，实施「删除接口基础地址、下线旧版搜索、接入 Exa」。决策与关键事实：

- Exa 接入（`@deepseek-ai/dsh-web-search-exa@0.2.1-rc.2`，随 dsh 主线同步发版；npm `latest` 标签停在 0.0.1 系属标签滞后，不代表插件停滞——本次核查曾据 latest 误判其为弃子）：
  - 启用方式：`packages/dsh-profile/cordis.patch.yml` 追加 `web-search-exa` 插件行，不带 config；主 `package.json` 与 profile 包依赖均声明，保证打包与 profile 解析。
  - 凭据链路：密钥经 `credentials/set` 以 `EXA_API_KEY` 引用保存，dsh 凭据后端写入 `~/.dsh/.env` 并注入引擎启动环境，插件构造时从环境读取。绝不向 `web-search-exa` 写 `apiKey` 字面值——插件 config 会出现在设置回显中，且显式空串会以 `??` 语义遮蔽环境回退。
  - 插件重建：Exa 插件在构造时快照环境密钥，凭据更新后须写入一次 `numResults`（合法配置字段）触发 Cordis 重建，新密钥才生效；因此 Exa 替换密钥的保存恒携带一次 `numResults` 写入，`configOps` 的 `reload` 参数即为此设计。
  - 服务切换语义：选 Exa 即 `searchProvider: exa` + `fetchProvider: http`（匿名公开抓取，不依赖 DeepSeek 密钥）；切回 DeepSeek 恢复 `deepseek-search-api` + `deepseek-fetch-api`。Exa 密钥为必填独立密钥，无「沿用模型密钥」选项。
