# Codex 模型接入问题记录

## 状态与范围

- 当前结论：引擎内置的 OpenAI Codex 供应商在当前引擎版本（`@deepseek-ai/dsh@0.2.1-rc.3`）下无法使用，青梧与官方桌面版一致受限。根因是 ChatGPT 账号授权登录没有对外接口，任何客户端都无法完成授权写入凭据库；本问题阻塞在上游，青梧侧无独立解法。
- 验证范围：本机引擎依赖源码（`dsh-llm-pi-ai`、`dsh-authorization`、`dsh-credentials-local`、全部 Typert 对外契约）、官方桌面版 0.2.1-rc.3 应用包与运行数据、本机 `~/.dsh` 配置与凭据库；2026-10-25 在官方桌面版实测选中 Codex 模型发送消息失败。
- 遗留事项：追踪上游版本是否将授权流开放为对外接口、官方桌面版是否提供 Codex 登录入口；开放后按下方「接入前提」实施。
- 日期：2026-10-25。引擎版本：`@deepseek-ai/dsh@0.2.1-rc.3`（与官方桌面版内置版本一致）。

## 关键事实

- `openai-codex` 是 pi-ai 目录中唯一仅支持 OAuth 的供应商：不接受 API 密钥（目录声明无任何密钥环境变量），仅支持浏览器登录 ChatGPT 完成授权，令牌由引擎授权流写入凭据库记录 `llm-pi-ai/openai-codex`。
- 引擎授权服务（`dsh-authorization`）只有进程内接口，未提供 Typert 对外契约；引擎全部对外 wire 方法清单中没有授权相关端点，官方界面插件中也没有发起该授权的调用。这是接入受阻的直接原因。
- 凭据库 `~/.dsh/.credentials.yaml` 为全部客户端全局共享（不按 profile 隔离）。任一客户端完成 ChatGPT 授权后，其他客户端的引擎即可读到该凭据；据此一次登录全机可用。
- profile 隔离仅覆盖配置层（插件组合、模型供应商路由、默认模型等）；会话、凭据、缓存均在 `~/.dsh` 根级共享。
- 引擎与官方桌面版均不读取 Codex CLI 的登录文件（`~/.codex/auth.json`），本机已有的 Codex CLI 登录态对 dsh 无作用。

## 官方桌面版同样不可用的证据

- `~/.dsh/.credentials.yaml` 的 records 段中无 `openai-codex` 记录：从未有任何客户端完成过 Codex 登录。
- desktop profile 的用户补丁中 `llm-pi-ai` 的 `providers` 为空映射（连路由都未声明），而默认模型指向 `openai-codex/gpt-6-sol`；会话投影中该模型选择状态为暂存、最后使用时间为空——选中从未转化为成功请求。
- 2026-10-25 在官方桌面版选中 Codex 模型发送消息，失败；同机另有一条官方桌面版会话，其助手回复在解释 `openai-codex` 需要 OAuth 授权。
- 官方桌面版应用包中无读取 Codex CLI 凭据的逻辑；`auth.json` 命中均为 pi-ai 文档文本。

## 青梧侧现象与原因

- 设置页把 Codex 按普通供应商渲染为 API 密钥表单；因该供应商仅接受 OAuth，填写并保存密钥不产生任何效果，表现为「配置无反应」。
- 模型选择器可以选中 Codex 模型（目录声明即可选），但发送消息时引擎因凭据缺失拒绝请求。

## 接入前提与计划

- 前提：上游将授权流开放为对外接口，或官方界面提供可对齐的登录交互。任一条件成立前不实施，避免自造与引擎脱节的授权通道。
- 实施内容：设置页为 Codex 提供「登录 ChatGPT」交互（替代无效的密钥表单），经引擎授权流写入共享凭据库；供应商路由经既有设置接口声明后即可使用。
- 短期替代（已可用）：添加自定义供应商，填写 OpenAI 官方 API 或兼容网关密钥；按调用量计费，与 ChatGPT 订阅额度无关，由使用者自行权衡成本。
