## Bug 修复

- [x] 运行中提交的消息在青梧界面无任何可见反馈：原因是提交走 `mode: "queue"` 后消息只进引擎 inbox，而界面只订阅日志事件、既无回显也无队列区。已实现：提交当帧插入本地回显（「发送中」），宿主落库或入队后自动退休；由 durable 事件 `agent/inbox/spliced` 折出待发送队列并在输入框上方常驻展示（「排队中」/「插话中」），行内支持编辑、删除、插话（走 `session/updateQueue`）；运行中草稿非空时同一位置改为「排队发送」按钮，不再只能靠 Enter 触发。待用户实机验证 ✅ 2026-09-11
- [x] 切换到正在运行的会话时右下角没有「停止」按钮：原因是 `api-session/status` 只在 running↔idle 跳变时发出，切换会话/重连不重放，而切换时界面无条件把运行态置为 false。已实现：切换会话时用 `session/list` 的 `Summary.running` 播种，并在每次列表刷新时对账兜底；空草稿显示「停止」、有草稿显示「排队发送」，不再出现右下角整块空掉 ✅ 2026-09-11
- [ ] 引擎重启后排队消息不会自动投递：队列项本身是 durable 事件，但引擎恢复会话时不唤醒队列，要再发一条消息才会被一起领走（界面现在会把队列显示出来，不会再「看不出问题」，但仍需决定是否做兜底）
- [x] 青梧界面的审批/问答回执全部静默失败（真正的病根，也是「提问卡片点了没反应、切官方界面才答得上」的原因）：`DshBridge.eventResult` 发 `POST /api/$events/result` 时把载荷写成 `{ clientId, eventId, outcome }`，而网关 `parseRemoteEventResultPayload` 只接受「恰好一个 plain-object `args` 字段」的载荷（`dsh-api-gateway` 第 922 行），于是请求被直接拒绝；桥又只把失败 `console.error` 到主进程日志，渲染层一无所知——卡片照旧消失、没有报错，宿主那边一直挂着等回答。已修：载荷改包 `{ args: {...} }`（与一元 RPC 同一信封规则），并把 `eventResult` 的返回改成 `DshRpcResult`，渲染层在失败时显示错误条、保留卡片不再假装成功（审批路径同样修好并加了 `clientId` 兜底）。已实机确认：青桐界面的提问回执能正常送达宿主 ✅ 2026-09-11
- [x] 输入框草稿不分会话：`input` 原本是全局单份状态，切换会话既不清空也不按会话保存，在会话 A 输入的文字会原样留在会话 B 的输入框里，回车即发到 B。已实现逐会话草稿（键为会话 id，无会话时用空串）：输入时即写入所属会话的草稿桶，切换会话载入目标会话的草稿，发出后清空、发送失败写回，会话被删除时清理该桶。仅存内存（重启不保留），如需「关掉应用草稿还在」再单独评估落盘 ✅ 2026-09-11
- [x] 提问卡片选择不可用且设计不达标：原因是选项都挤在同一行小按钮里、点完卡片既不消失也不清理本地状态（宿主只向其他客户端推 `cancel` 帧），重复点击被宿主静默忽略；且一次只提交单题答案，多题请求会拿到不完整回答。已重做：一题一区、纵向选项行（label + description，单选/多选标记）、整请求一次提交该请求下所有题目、每题可填「其他」自由文本（单选时与选中项互斥）、可「跳过此问题」（提交空 selected）、提交成功后卡片即时移除、失败保留并报错；识别 plan-review 意图并改为「计划审批」布局（计划 markdown 限高滚动 + 批准/拒绝按钮 + 「讨论一下」以 ASK_CANCELLED 拒绝等待，把控制权交回输入）；回执 `clientId` 为空时改取当前事件流身份，仍为空则明确报错而不是静默失败。已实机确认：青桐界面提交可正常送达宿主 ✅ 2026-09-11
- [x] 新建会话落在「无问候语、正文全空」的会话页：点「新会话」时 `createSessionIn` 会立即在宿主建出（或复用）一个空白会话并 `setCurrentId`，而引导页（居中问候 + 居中输入框）的渲染条件只看 `!currentId`，于是用户看到顶栏只有工作区名、正文一片空白、输入框贴底的页面——其他产品在第一条消息发出前都停留在新会话引导页。修复：引导页条件改为「未选中会话，或当前会话仍为 blank、无任何消息事件且未在运行」，发出第一条消息后自然切换为会话态 ✅ 2026-09-11
- [x] 空输入时看不到发送按钮：原因是 `.native-send.empty { visibility: hidden }`（自 2026-09-11 视觉对齐第二批起）把按钮整块藏掉，只有输入字符后才出现，用户找不到发送入口。改为常显禁用态：草稿为空时显示灰色圆钮（灰底 + 边框 + 灰箭头、不可点），有草稿后恢复蓝底可点，运行中空草稿仍是「停止」；已删除 `.empty` 规则与对应类名。待用户实机验证 ✅ 2026-09-11
- [x] 不断弹出终端窗口（v0.0.7 已修问题的回归）：根因是 GUI 子系统进程（Electron/electron.exe）不继承父进程控制台，而 dsh 用 `process.execPath` 逐层派生 Windows Job runner 与 windows-acl runner，整条链都没有控制台，最后那条 pwsh 只能自己新建一个可见控制台窗口（0.1.5-rc.1 引入新派生层后暴露，0.1.5-rc.2 仍未改变该派生方式；旧版每次派生自带 `windowsHide` 掩盖了它，主进程 `acquireHiddenConsole()` 的隐藏控制台也到不了引擎树）。改为用控制台子系统的官方 Node 运行时装包内启动引擎：版本与 Electron 内置 Node 对齐（24.18.1），`scripts/fetch-node-runtime.cjs` 按官方 SHASUMS256 校验后解出，`extraResources` 随包、`before-pack` 钩子保证就绪（失败即打包失败），引擎/runner/pwsh 因此全部继承主进程隐藏控制台；找不到运行时或主进程拿不到控制台时退回 Electron 方式。代价：安装包增大约 35 MB。待用户实际运行验证（开发态已实测：命令无控制台、不弹窗；打包态待发版验证） ✅ 2026-09-11
- [x] 引导页切换项目报「workspace/insertSessionBefore 失败：workspace/move-invalid…the session is not accounted」：原因是项目 chip 用该接口把当前会话「搬」到目标项目，而引擎的工作区归属在会话创建时按目录写死、该接口只受理已登记在本项目的会话，跨项目一律被拒（会话还是空的也一样）。已改为对齐官方口径——chip 切换的是新会话落点：在目标项目建/复用一个空白会话再切过去，未发送的草稿随人迁移，原来那个空白会话留在原项目、下次进入时复用；并移除已无引用的 workspace/insertSessionBefore 协议项 ✅ 2026-09-11
