# 安装升级反复提示无法关闭

## 当前结论

- **状态：源码修复与真实 NSIS 隔离回归已完成，尚未发布；真实存量应用的原地升级与交互式提权退出待验收。**
- v0.3.2 使用 electron-builder / app-builder-lib 26.18.0、electron-updater 6.8.11，沿用默认 NSIS 卸载逻辑。
- 主要故障是旧版卸载器的原子迁移操作触及 Windows 传统路径长度限制。安装目录中的文件路径未超限，但迁移到 `%TEMP%\ns*.tmp\old-install` 后，最长目标路径可能达到 260 个字符。该卸载代码使用的普通路径访问方式不能完成移动，随后回滚并返回退出码 2。
- NSIS 临时目录名称长度会变化：隔离实验中生成的临时目录前缀相差一个字符，对应最长目标路径分别为 259 与 260 字符。前者成功，后者失败。这解释了重试结果不稳定的机制；不能将重试后偶尔成功视为已修复。
- 安装器把旧卸载失败也归入“无法关闭”提示，掩盖了真正的文件迁移错误。退出码 2 是此次 NSIS 卸载失败状态，不能直接按 Win32 错误码 2 解读为文件不存在。
- 另确认一个独立缺陷：安装器外层提权包装进程退出时，执行了已经卸载的 `UAC.dll` 中的窗口回调地址，发生执行访问违规。该崩溃发生于安装器退出后段，不与最初的卸载失败混作一个根因。

## 2026-11-06：现场与复现实验

### 1. 历史修复与覆盖缺口

这项修复仍保留在当前源码中。它没有改动 NSIS 的旧版本卸载与临时文件迁移，也没有验证真实 Windows 覆盖升级。修复前的 Release 工作流运行应用质量检查与安装包构建，未运行安装升级回归。因此，历史修复及当时门禁通过不能证明本问题已经解决。

### 2. 真实覆盖安装

受控覆盖安装前正常退出应用，日志显示引擎于 13:56:38 结束。安装器于 13:57:31 启动；五次旧卸载尝试分别返回退出码 2。每次失败后，对安装目录中的 44 个 EXE、DLL、原生扩展及 ASAR 文件进行 Restart Manager 只读查询，未发现关联进程。该查询范围不覆盖全部普通文本文件，也不代表所有内核级占用均被排除。

再次重试时，捕获了真实迁移目录：

`%TEMP%\nssA1A1.tmp\old-install`

最长目标对应：

`resources\app.asar.unpacked\node_modules\@deepseek-ai\dsh-experimental-inspector\lib\devtools\models\issues_manager\descriptions\selectElementAccessibilityInteractiveContentAttributesSelectDescendant.md`

在本机，该文件位于安装目录下时完整路径长 226 字符，迁移目标完整路径长 **260 字符**。14:06:49，旧卸载器再次以退出码 2 结束。失败后原目录仍有 14,885 个文件，主程序、卸载器、ASAR 与引擎入口均存在。

### 3. 隔离对照

测试仅创建空白文件，复制相对路径结构，不复制应用配置、会话或文件内容。使用当前依赖中的 `un.atomicRMDir` 函数和缓存的 NSIS 3.0.4.1 编译器；未手工修改正式安装产物。

| 实验 | 结果 |
| --- | --- |
| 同一文件，固定迁移目标为 259 字符 | 迁移成功，函数返回 0 |
| 同一文件，固定迁移目标为 260 字符 | 迁移失败，源文件仍在、目标不存在；在该 NSIS 进程内重复调用普通 `MoveFileW` 返回错误 3 |
| 同一 260 字符目标，迁移时使用 `\\?\` 扩展长度路径 | 成功，函数返回 0 |
| 14,885 个空白文件，原始默认迁移代码 | 失败，停在上述最长文件 |
| 同样的 14,885 个空白文件，对临时目录创建和文件移动使用扩展长度路径 | 全部迁移成功，源目录剩余文件数为 0 |

单变量对照与真实失败路径一致，确认本次故障不需要进程占用即可触发。测试通过仅证明修复方向可行，不能替代正式安装包的完整升级和回滚回归。

### 4. 提权包装器退出崩溃

首次安装结束阶段，Windows 于 13:44:51 和 13:44:55 记录同一外层安装进程的两次异常：

- `0xc0000005`：执行访问违规，异常参数为执行操作 `8`，目标地址 `0x1000212f`。
- `0xc000041d`：后续用户回调异常，地址相同。

读取本机两份转储，仅提取异常记录、模块地址与代码指针，未导出内存内容：

- `UAC.dll` 位于已卸载模块列表，原基址 `0x10000000`，大小 `0x7000`。
- 异常地址为该已卸载模块偏移 `0x212f`，调用栈中的代码指针来自 `user32.dll`。
- 当前打包缓存中的 Unicode UAC DLL 时间戳为 `0x5564cd40`，对应 2015 年的插件；该偏移的代码为返回 false 的窗口回调，与官方源码的 `SplashDialogProc` 相符。

插件官方页面已将其标记为弃用、停止维护。这是安装器可靠性的另一项问题，不能仅通过修正错误提示或应用退出逻辑解决。

受控覆盖安装取消后，外层安装进程于 14:07:36 / 14:07:38 再次产生相同的两种异常。两份新转储中的地址仍为已卸载 `UAC.dll` 的 `0x1000212f`，表明该退出崩溃在本次受控验证中也可复现，与文件迁移失败分别保留处理。

受控安装取消后，重新启动 v0.3.2。应用日志于 14:08:06 记录内置引擎服务就绪；随后重新显示主窗口。未执行删除会话或配置的操作，未发起模型请求。

## 2026-11-06：源码修复与自动回归

### 实现

- `patches/app-builder-lib+26.18.0.patch` 修正上游 NSIS 源模板。`scripts/patch-nsis.cjs` 核对包版本、原始源码 SHA-256 和补丁的完整文件集合，所有文件通过校验后再写入；可重复执行。未应用或漂移的源模板不能通过 `check:deps` 与 `beforePack`。
- 查找、目录创建、文件迁移、恢复与安装目录删除使用 `\\?\` 扩展长度路径，不删除特定长文件、不依赖重试次数和临时目录碰巧变短。
- 覆盖升级不再复制并执行已部署的卸载器，而是在原有 `uninstallOldVersion` 流程中提取本次构建的卸载器；保留原有安装目录、安装范围、快捷方式和保留用户数据参数。卸载器启动失败或返回非零时停止安装，不能回退到旧卸载器继续尝试。
- `UAC_RunElevated` 与 `UAC_PageElevation_RunElevated` 在创建提权窗口前加载并通过 `GetModuleHandleExW(GET_MODULE_HANDLE_EX_FLAG_PIN)` 固定 UAC 模块；进程终止后由操作系统回收，避免先卸载代码再销毁窗口。
- 沿用 electron-builder 的默认安装脚本与卸载器生成、签名流程，不使用会跳过默认安全检查的全量自定义安装脚本。未更改应用版本号。

### 已验证结果

- 干净 `npm ci` 后补丁自动生效。
- `npm run check`：225 项测试、类型检查、依赖核对与界面构建通过。
- `npm run test:installer`：7 个子场景通过（含原始故障对照），测试器汇总为 8 项通过。
- `npx electron-builder --win --publish never`：完整应用 Windows 安装包、blockmap 与 `latest.yml` 构建通过；没有推送发布，也没有覆盖现有安装。
- 长路径回归使用正式补丁后的源函数，由相同 NSIS 编译器构建后执行；原始故障对照通过反向应用版本化补丁还原上游源码，不以模拟文件系统代替 Windows 行为。
- 兼容升级回归在独立注册信息下放入一旦被执行就返回 2 的旧卸载器，再执行修复版覆盖安装，确认新卸载路径确实绕过旧程序。后续覆盖与卸载均保留独立的测试会话标记。
- UAC 实验确认固定后两次 `FreeLibrary` 不会移除模块；未触发真实提权窗口，不能据此宣称原始交互现场已全部验收。

## 修复约束

1. 修改安装源码或生成配置后重新构建，不能直接改已发布安装器或其内嵌卸载程序。
2. 修复文件迁移、失败回滚及目录处理的长路径能力；不以删除某一个长文件、扩大等待时间或反复重试作为根治方案。
3. 保留真实错误信息，区分进程仍在运行、旧卸载失败和新文件写入失败。
4. 首次升级会执行**已经安装的旧卸载器**。只生成一个修好的新卸载器，不能保证旧版本到修复版的首次升级成功；必须单独处理并验证这条兼容路径。
5. 保留用户会话和配置，验证覆盖安装失败后的可用性；不以跳过失败、无条件清空安装目录或退出码伪装成功替代可靠处理。
6. UAC 退出崩溃与长路径失败分别验证，不能用其中一项修复通过代表整个升级链路通过。
