# Windows 任务栏图标回退 Electron 默认图标问题记录

## 现象描述

Windows 安装版（打包后运行的客户端）在任务栏或启动后，应用图标未显示正式的蓝底白色梧桐叶品牌图标，而是回退显示为 Electron 框架底层的默认原子轨道图标（黑灰底色、浅色环绕原子核）。该问题在版本更迭与重新安装后出现过两次，属于易复发缺陷。

## 已知事实与触发环境

1. **界面内正常，仅系统层异常**：青梧窗口自定义标题栏左上角、关于页面等前端渲染区域图标正常显示（渲染层使用 Base64 图片直接加载），说明品牌图标素材本身完好，异常仅发生在 Windows 操作系统级（任务栏、窗口类、Alt+Tab 切换等 Win32 系统层）。
2. **无需固定到任务栏即可稳定触发**：
   - 经实机验证，**该问题无需将应用固定到任务栏**；用户即使从未固定应用，从开始菜单或桌面快捷方式直接打开青梧，任务栏上动态弹出的正在运行的窗口图标，也会直接显示为 Electron 默认原子图标。
   - 属于**第二次重复出现**：此前曾通过手动删除某个图标/图片缓存文件恢复过一次，但本次版本更迭或重新安装后再次复发，证实属于代码与打包机制层面的确定性缺陷，而非偶发固定项污染。
3. **打包产物中的图标路径缺陷（核心根因）**：
   - 目前 `package.json` 的 `build.files` 将 `build/icon.ico` 打包入 `app.asar` 归档内，但未在 `extraResources` 中提供外部物理图标。
   - `src/main/window.ts` 中的 `getIconPath()` 在生产环境中命中了 `path.join(app.getAppPath(), "build", "icon.ico")`（即 `resources/app.asar/build/icon.ico`）。虽然 Electron Hook 的 Node.js `fs.existsSync` 返回 `true`，但 Windows Win32 原生 API（`WM_SETICON`、`LoadImageW`）无法解析 `app.asar` 归档内部路径，导致窗口启动时未能成功将真实图标句柄注入操作系统。
4. **AppUserModelId 与系统图标缓存机制**：
   - 应用在启动时显式调用了 `app.setAppUserModelId("com.qingwu.desktop")`。
   - 当窗口未向操作系统正确注入原生图标句柄时，Windows 任务栏会根据该 `AppUserModelId` 尝试从系统图标缓存（`IconCache.db` / `iconcache_*.db`）匹配已知图标；若缓存记录了旧默认图标或匹配失败，Windows 就会强制回退显示框架底层默认的原子图标。此前删除缓存能临时起效，正是因为强行清空了 Windows 对该 AppId 的错误历史记录，但因代码依然无法向原生层提供物理图标，新缓存建立时极易再次退回默认图标。

## 临时规避操作（用户侧）

在未固定任务栏的情况下，若运行窗口依然显示默认原子图标，此前生效的临时缓解方案是清理 Windows 系统图标缓存：

1. **彻底退出应用**：关闭窗口，并在右下角系统托盘菜单中彻底点击「退出」青梧。
2. **清理 Windows 图标缓存**：
   - 按快捷键 `Win + R` 打开运行窗口，输入 `%localappdata%` 并回车；
   - 在文件夹中找到隐藏文件 `IconCache.db`（需开启“显示隐藏文件”），直接将其删除；
   - 或按 `Ctrl + Shift + Esc` 打开任务管理器，找到「Windows 资源管理器」，右键选择「重新启动」。
3. **重新打开应用**：重新从开始菜单或桌面快捷方式打开青梧，Windows 会重新生成图标缓存。
*(注：临时删除缓存只能维持当次，若底层代码未将物理图标注入 Win32 原生层，后续安装或系统刷新时仍会复发。)*

## 工程根治方案与实施结果（2026-09-27 已落地）

1. **图标物理外置（资源解包）**：
   - 在 `package.json` 的 `build.extraResources` 中，新增将 `build/icon.ico` 与 `build/icon.png` 复制到安装目录的 `resources/` 外部物理路径（`resources/icon.ico` 与 `resources/icon.png`）。
   - 彻底避免将图标仅封在 `app.asar` 虚拟包内，向 Windows 系统层提供稳定可靠的物理文件路径。
2. **主进程多层兜底与 NativeImage 内存图元绑定**：
   - 在 `src/main/window.ts` 中重构 `getIconPath()`，优先检索 `resources/icon.ico` 外部物理路径；
   - 新增 `getIcon()` 方法，通过 `nativeImage.createFromPath` 生成内存中的 NativeImage 实例，同时在 `new BrowserWindow({ icon })` 及窗口创建后显式调用 `win.setIcon(iconImage)` 进行原生句柄双重绑定；
   - 系统托盘（`tray.ts`）与桌面通知（`notification.ts`）同步适配 `NativeImage` 与真实路径双模式。
3. **验证结果**：
   - 质量门禁（`npm run check`）全部跑通：类型检查 0 错误，81 项单元测试全部通过（pass 81, fail 0），Vite 打包编译正常。将在下一个发布包（v0.2.6+）中正式生效。
